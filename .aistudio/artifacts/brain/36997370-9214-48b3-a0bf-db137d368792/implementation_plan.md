# Ame Player 无限播放歌单识别与动态推荐队列方案

为 Ame Player 引入智能歌单/卡片类型识别与无限推荐播放模式（Infinite Radio Queue），使单曲推荐卡片、带种子歌曲的雷达/漫游歌单、私人 FM 与心动模式能够从特定种子单曲立即起播，并在播放或切歌过程中按需静默续接无限推荐曲目。

## 用户确认与关键决策

> [!IMPORTANT]
> 以下核心产品与技术决策已根据您的偏好确认，将在批准后直接指导实现：

- **已确认决策 1 — 触发无限播放模式的入口范围**：
  1. **单曲类推荐卡片**：首页风格精选（如「专属你的治愈精选」）、新歌推荐等 `resourceType = "song"`（或 `action = "play_all_song_from_current_index"`）的卡片。
  2. **私人 FM 与心动模式入口**：首页顶部龙珠中的「私人 FM」（`orpheus://privatefm` / `id = -6`）与「心动模式」。
  3. **带种子歌曲的雷达或漫游歌单**：首页推荐中 `logInfo` 携带非空 `relatedSong` 种子单曲 ID 的卡片（例如「今天从《Happy Now?》听起 | 私人雷达」、「从《Did You Like Her In The Morning?》开启宝藏音乐环游 | 宝藏雷达」）。
  - *注：不含种子歌曲的普通 `specialType = 100` 官方雷达歌单仍保持传统固定歌单详情页浏览模式。*
- **已确认决策 2 — 混合推荐接口策略**：
  - **单曲漫游 / 种子雷达歌单**：基于当前队列种子歌曲调用相似歌曲推荐接口（`/api/v1/discovery/simiSong` / `/simi/song`），同时支持本地曲库优先匹配替换。
  - **私人 FM**：调用网易云私人 FM 接口（`/api/v1/radio/get` / `/personal_fm`）持续拉取个性化电台曲目。
  - **心动模式**：基于用户红心/首选歌单 ID 与起始单曲 ID 调用智能推荐列表接口（`/api/playmode/intelligence/list` / `/playmode/intelligence/list`）。
- **已确认决策 3 — 预加载缓冲与历史保留队列策略**：
  - 维护带历史记录的动态追加队列：当处于无限推荐模式且队列剩余未播曲目数 **少于 2 首**（`playlist.size - 1 - currentIndex < 2`）时，后台静默拉取下一批推荐歌曲并去重追加至 ExoPlayer 队列尾部；用户仍可通过「上一首」或播放队列抽屉回溯已播历史。

## 1. 核心概念与工作方式

- **功能概述**：
  - 区分网易云首页中的「静态列表容器（传统歌单、专辑）」与「流式单曲/电台入口（单曲漫游、种子雷达、私人 FM、心动模式）」。
  - 点击传统歌单时进入歌单详情页；点击无限播放类入口时，无需进入空详情页或一次性拉取死板的固定曲目，而是立即创建对应的**无限播放会话（Infinite Playback Session）**，将起始种子歌曲加入全新播放队列并即刻起播，随后根据播放进度与手动切歌事件自动续接推荐单曲。
- **目标场景**：
  - 用户在首页点击「今天从《XXX》听起」、「专属你的精选单曲」或「私人 FM / 心动模式」时，获得与网易云音乐原生客户端一致的“即点即播、无限漫游”体验。
- **核心价值**：
  - 消除原先将单曲卡片 ID 当作歌单 ID 请求导致的“未获取到歌单曲目”错误，并还原种子雷达歌单“从指定单曲开启无限推荐”的原生交互。

## 2. 用户体验与视觉设计

- **关键用户流程**：
  1. **首页卡片识别与角标提示**：
     - 在首页「推荐歌单」、「雷达歌单」、「风格精选」及「顶部龙珠」中，具有无限漫游属性的卡片（单曲卡片、带 `relatedSong` 种子歌曲的雷达卡片、私人 FM/心动模式）在封面角落展示精致的漫游/电台标识（如无限符号 `∞` 或电台徽章），与普通歌单的播放量角标清晰区分。
  2. **即点即播与 Toast 反馈**：
     - 用户点击无限播放入口后，底部 MiniPlayer 立即弹出并开始播放起始种子歌曲，同时轻提示当前激活的模式（如 `正在从《Happy Now?》开启私人漫游` 或 `已开启私人 FM`）。
  3. **播放页与队列抽屉状态展示**：
     - 在全屏播放页与播放队列抽屉顶部标题栏旁，展示当前激活的无限推荐模式胶囊标签（如 `私人 FM · 无限推荐中`、`单曲漫游 · 无限推荐中`、`心动模式 · 智能推荐`），并提供一键切换回普通列表模式的开关或随用户主动切换普通歌单时自动退出无限模式。
  4. **无缝切歌与静默续接**：
     - 当歌曲自然播完、或用户在播放页/MiniPlayer/系统媒体通知栏点击「下一首」使得剩余待播曲目不足 2 首时，后台自动请求对应推荐接口并向队列尾部追加新曲目；若用户处于最后一首且推荐仍在加载中，点击「下一首」会触发即时拉取并自动跳转播放。
- **视觉风格与主题适配**：
  - *美学方向*：延续 Ame Player 现有的沉浸式流光模糊（Salt Player 风格高饱和背景 + Material 3 现代圆角卡片）视觉语言。
  - *色彩与层级*：无限模式胶囊标签采用半透明毛玻璃表面配合主题强调色（`MaterialTheme.colorScheme.primaryContainer` / 全屏播放页高对比亮色胶囊），避免突兀的硬编码色块。
  - *动效反馈*：队列追加新推荐歌曲时保持列表平滑过渡，不打断当前歌词滚动与封面渲染。

## 3. 核心产品决策与技术权衡

- **决策 1：多维特征联合判定歌单/卡片类型**
  - *采用方案*：在解析首页 Block 与 Creative 时，同时提取 `creativeType`、`resourceType`、`action` 以及 `logInfo` 中的 `relatedSong` 字段，构建统一的加载类型枚举（固定歌单 vs. 单曲漫游 vs. 种子雷达漫游 vs. 私人 FM vs. 心动模式）。
  - *原因*：网易云首页接口中，“今天从《XXX》听起 | 私人雷达”的 `resourceType` 仍为 `"list"`，唯有解析 `logInfo` JSON 中的 `relatedSong` 才能准确获知其“从特定单曲开始”的种子属性；而风格精选卡片的 `resourceType` 为 `"song"`，`resourceId` 本身即为单曲 ID。联合判定可确保零误判。
  - *备选方案对比*：若仅凭标题正则匹配 `《.*》`，无法拿到准确的种子单曲 ID；若将所有 `specialType = 100` 均当作无限歌单，则会误伤普通官方精选歌单。
- **决策 2：在播放引擎层（PlayerEngine）内建无限推荐状态机与预加载器**
  - *采用方案*：在播放引擎中维护当前激活的无限播放模式上下文（`InfinitePlayMode`）与已推荐去重集合（`seenTrackIds`），监听 `onMediaItemTransition` 与 `skipToNext` 触发水位线检查（剩余 < 2 首时异步拉取并调用 `exoPlayer.addMediaItems`）。
  - *原因*：将预加载与续播逻辑下沉至播放引擎层，可保证无论用户是在 App 内操作、锁屏系统媒体控件切歌、还是后台息屏自然播完，都能可靠触发下一首推荐加载。

### 数据模型与状态设计

1. **首页卡片识别模型扩展**：
   - 在首页 `HomepageBlock.Creative` 中补充：
     - `resourceType: String`：区分 `"list"`（歌单）、`"song"`（单曲）、`"album"`（专辑）等。
     - `action: String`：识别 `orpheus://privatefm`、`play_all_song_from_current_index` 等动作指令。
     - `seedSongId: String?`：从 `logInfo` JSON 的 `relatedSong` 字段（或当 `resourceType == "song"` 时的 `resourceId`）解析出的起始种子歌曲 ID。
   - 新增辅助判定方法：
     - 当 `resourceType == "song"` 时，判定为 **单曲漫游模式（`SONG_RADIO`）**，`seedSongId = resourceId`。
     - 当 `resourceType == "list"` 且 `seedSongId != null`（即 `logInfo.relatedSong` 非空）时，判定为 **种子雷达漫游模式（`SONG_RADIO`）**，以 `seedSongId` 作为第一首播放曲目，同时记录原雷达歌单曲目作为相似接口无结果时的兜底池。
     - 当龙珠为「私人 FM」（`id == -6L` 或名称含 `FM`）时，判定为 **私人 FM 模式（`PERSONAL_FM`）**。
     - 当龙珠为「心动模式」（名称含 `心动`）时，判定为 **心动智能模式（`HEARTBEAT_INTELLIGENCE`）**。
2. **播放引擎无限模式状态（`InfinitePlayMode`）**：
   - `NONE`：常规固定列表模式（加载普通歌单、专辑、本地歌单时自动重置为 `NONE`）。
   - `SONG_RADIO(currentSeedSongId: String, fallbackPlaylistId: Long?)`：单曲/雷达漫游模式，每次以队列最新曲目或种子曲目请求相似歌曲。
   - `PERSONAL_FM`：私人 FM 模式，每次调用私人 FM 接口续接新曲目。
   - `HEARTBEAT(playlistId: Long, seedSongId: String)`：心动模式，调用智能列表接口获取推荐队列並支持循环续接。

### 关键交互与状态流转映射

- **启动无限播放会话（`startInfinitePlayback`）**：
  1. 重置去重集合 `seenTrackIds`，设置当前 `infinitePlayMode`。
  2. 若已有起始单曲对象（或通过 `getSongDetails(listOf(seedSongId))` 获取首曲详情），先通过 `playlistManager.findLocalMatch` 检查本地高音质匹配，立即调用 `loadPlaylist(listOf(firstTrack), 0, keepInfiniteMode = true)` 并执行 `play()`，实现零等待起播。
  3. 同步触发首次后台预加载（`ensureInfiniteQueueBuffer()`），拉取后续推荐曲目并通过 `appendMediaItems` 静默加入队列尾部。
- **队列水位线检查与续接（`ensureInfiniteQueueBuffer`）**：
  1. 触发时机：首次起播后、`onMediaItemTransition` 切歌时、以及用户在队尾点击 `skipToNext()` 时。
  2. 判定条件：`infinitePlayMode != NONE` 且 `(playlist.size - 1 - currentIndex) < 2` 且当前无正在进行的预加载任务。
  3. 去重与兜底：过滤已在 `seenTrackIds` 中的歌曲；若相似歌曲接口返回为空（例如冷门曲目或未登录受限），在种子雷达模式下自动从原雷达歌单剩余曲目中抽取补充，或基于前序种子歌曲继续推荐，确保无限播放永不断流。
