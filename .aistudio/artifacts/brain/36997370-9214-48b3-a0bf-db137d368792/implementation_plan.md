# Ame Player 全局 AOSP 预见性返回手势方案

为 Ame Player 引入完整的 Android 原生预见性返回（Predictive Back）手势体验。通过结合系统级 `OnBackInvokedCallback` 桌面预览与 Compose 层级的 `PredictiveBackHandler` 实时手势流驱动，实现跨页面与页内视图的跟手缩放、圆角形变及底层页面实时透视预览，并在返回桌面时保持后台音频服务不中断。

## User Review & Critical Decisions

> [!IMPORTANT]
> 以下关键设计与交互决策已根据您的偏好确认，将在批准后直接进入代码实现：

- **确认决策 1 — 跨页面跟手缩放透视动效**：手势从屏幕左/右边缘滑入时，前景页面跟随手指进度实时缩小、增加圆角并向手势反方向微移，同时底层页面以微缩视差态实时透出并随手势进度恢复至原始比例。
- **确认决策 2 — 全层级应用内手势覆盖**：预见性返回动效覆盖应用内全部核心视图层级，按优先级从高到低依次响应：
  1. **播放队列 → 播放页主视图**（实时驱动 3D 视差景深还原）
  2. **全屏歌词 → 播放页封面视图**（实时插值封面大小、位置与歌词透明度）
  3. **设置页 / 播放页 → 主界面**（叠层渲染主界面，前景跟手缩放退回）
  4. **歌单详情页 → 歌单列表**（列表常驻底层，详情卡片跟手缩放滑出）
- **确认决策 3 — 根层级原生返回桌面预览与后台保活**：移除根 Activity 的硬拦截，启用系统级 `enableOnBackInvokedCallback` 以展示原生返回桌面缩略图动画；同时解耦 Activity 销毁与单例播放引擎生命周期，确保退回桌面后前台音乐服务与实况通知持续播放。

## 1. Overview & Core Concept

- **功能定位**：将传统的“松手即切页”离散返回升级为连续、可随时中断撤回的物理跟手预见性返回体验。
- **核心价值**：
  - **视觉连续性**：用户在滑动过程中即可透过缩小的当前视图预览下一层界面，确认返回目标；若中途反向滑回取消手势，视图将平滑回弹恢复。
  - **系统级原生融合**：在主界面根层级向内滑动时，直接触发 Android 14+ 原生返回壁纸与桌面图标的缩略预览动效，同时保证音乐后台无感续播。

## 2. User Experience & Visual Design

### 关键用户手势流 (Key User Flows)

1. **播放页内部层级返回**：
   - **从播放队列返回**：当竖屏播放队列展开时，从屏幕边缘向内滑动，队列层随手势进度实时向下滑退并缩小，底部的播放主界面同步从 `0.92x` 景深缩放态平滑放大恢复至 `1.0x`。
   - **从全屏歌词返回封面**：当处于全屏歌词模式（且队列未展开）时，边缘滑动将实时逆向驱动封面插值进度（`1.0 → 0.0`），左上角迷你封面跟随手指实时放大归位至中央大图，全屏歌词渐隐、单行歌词与控制栏渐显。
2. **跨顶层页面返回（播放页 / 设置页 → 主界面）**：
   - 滑动返回时，主界面（包含导航栏与迷你播放条）保持在底层可见；顶层的播放页或设置页随手势进度缩放（最高缩至 `0.88x`）、四周呈现 `28.dp` 柔和圆角与阴影，并跟随手势边缘（左/右）与纵向触点位置产生自然的物理偏移。
3. **歌单详情返回歌单列表**：
   - 在“我的歌单”标签页内查看歌单详情时，边缘滑动使歌单详情页跟手缩小并横向偏移，底层的歌单网格/列表实时透出并由暗变亮。
4. **主界面根层级返回桌面**：
   - 当处于主界面顶层且无子页面展开时，所有应用内 `PredictiveBackHandler` 均自动让出控制权，由 Android 系统接管并渲染原生的“应用窗口缩小透出系统桌面”预见性返回动画。

### 视觉与动效参数规范 (Visual & Motion Specs)

- **跟手形变曲线**：
  - **缩放比例 (`scale`)**：随手势 `progress` 从 `1.0f` 线性/阻尼过渡至 `0.88f`。
  - **动态圆角 (`cornerRadius`)**：手势启动瞬间至进行中，前景容器圆角从 `0.dp` 平滑过渡至 `28.dp`，贴合现代手机屏幕物理圆角。
  - **边缘感知位移 (`translationX` / `translationY`)**：识别 `BackEventCompat.swipeEdge`（左边缘 `EDGE_LEFT` 或右边缘 `EDGE_RIGHT`），向屏幕内侧产生柔和跟手位移，并结合触点纵向位置产生微幅垂直跟随。
  - **底层景深视差**：底层主视图在手势初期处于 `0.95f` 微缩与暗色遮罩状态，随手势推进逐步恢复至 `1.0f` 满屏与完全不透明。
- **手势完成与取消回弹**：
  - **完成提交**：当用户松手确认返回，前景视图沿当前速度与方向快速完成淡出/滑出收尾，状态正式切换。
  - **中途取消**：当用户滑回屏幕边缘取消返回，捕获 `CancellationException` 并使用 `spring` 弹性动画将缩放、位移与圆角平滑回弹归零。

## 3. Key Product Decisions & Trade-Offs

- **决策 1：采用叠层渲染（Layered Box Stack）替代纯互斥 `AnimatedContent`**
  - *方案选择*：在主界面与播放页/设置页之间、以及歌单列表与歌单详情之间，采用底层常驻（或在激活及手势过渡期双层共存）的叠层布局，而非单一 `AnimatedContent` 互斥替换。
  - *原因*：`AnimatedContent` 在仅修改目标状态前不会同时渲染底层视图；而预见性返回要求在手指滑动阶段（状态尚未最终提交前）就能实时看到底层页面的真实内容。
  - *备选方案对比*：若仅在松手提交后才触发 `AnimatedContent`，手指滑动期间底层只能显示纯黑或纯色背景，无法实现真正的“透出底层页面”预览效果。

- **决策 2：解耦 `MainActivity` 销毁生命周期与 `AmePlayerEngine` 释放**
  - *方案选择*：移除 `MainActivity` 根部的 `onBackPressedDispatcher` 拦截回调，并在系统通过预见性返回关闭 `MainActivity` 时保持单例 `AmePlayerEngine` 与前台 `AmePlaybackService` 存活。
  - *原因*：Android 系统的原生返回桌面缩略预览要求根 Activity 不注册激活态的返回拦截器；一旦移除了 `moveTaskToBack(true)` 拦截，系统完成手势后会正常结束 `MainActivity`。解耦引擎释放可确保界面退出后音乐播放、媒体会话与实况通知依然无缝运行。

## 4. Technical Architecture & Data Strategy

### 架构与手势分层路由图

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Android System OnBackInvokedDispatcher               │
│                 (android:enableOnBackInvokedCallback="true")            │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ BackEventCompat Stream (progress, edge, touchY)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                     In-App PredictiveBack Priority Chain                │
│                                                                         │
│  [Priority 1] 播放队列展开态 (showPlayQueuePage == true)                  │
│       └──► 实时逆向驱动 queueProgress (1f -> 0f)，还原播放页 3D 景深      │
│                                                                         │
│  [Priority 2] 全屏歌词展开态 (isLyricsMode == true)                       │
│       └──► 实时逆向驱动封面/歌词插值 progress (1f -> 0f)，迷你封面放大归位  │
│                                                                         │
│  [Priority 3] 顶层设置页 (showSettingsScreen == true)                    │
│       └──► 前景设置页缩放/圆角/偏移 + 底层主界面或播放页实时透视恢复       │
│                                                                         │
│  [Priority 4] 顶层播放页 (showPlayerScreen == true)                      │
│       └──► 前景播放页缩放/圆角/向底部微移 + 底层主界面实时透视恢复         │
│                                                                         │
│  [Priority 5] 歌单详情视图 (selectedPlaylistForDetail != null)           │
│       └──► 前景歌单详情缩放/圆角/偏移 + 底层歌单列表实时透视恢复           │
│                                                                         │
│  [Fallback] 主界面根层级 (全部应用内拦截器 enabled = false)               │
│       └──► 交由 AOSP 系统执行原生返回桌面缩略预览动画，后台服务继续播放    │
└─────────────────────────────────────────────────────────────────────────┘
```

### 手势状态模型与交互映射

- **通用预见性手势状态 (`PredictiveBackState`)**：
  - 记录实时手势进度 `progress: Float (0f..1f)`、触发边缘 `swipeEdge: Int`、以及触点相对偏移量。
  - 提供统一的 `Modifier.predictiveBackLayer(...)` 图形变换扩展，利用 `graphicsLayer` 高效执行 GPU 级缩放 (`scaleX`/`scaleY`)、位移 (`translationX`/`translationY`)、透明度 (`alpha`) 与动态圆角裁剪，避免手势过程中的重组开销。
- **页内动画直连驱动**：
  - 在播放页内部，手势流不依赖外层容器缩放，而是直接调用 `Animatable.snapTo(1f - backEvent.progress)` 将用户手指位置与现有的封面-歌词过渡动画、队列视差动画 1:1 绑定，松手取消时 `animateTo(1f)`，松手确认时 `animateTo(0f)`。
